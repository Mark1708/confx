# Автономная Lorem-песочница Confx

Локальная лаборатория для экспорта и обновления синтетических страниц через настоящее расширение Confx. Без Docker, аккаунта Atlassian, рабочих выгрузок и доступа к рабочей wiki.

**Это совместимый тестовый контракт, а не Confluence.** Здесь независимо реализованы ограниченные преобразования Storage XML ↔ HTML редактора и HTML просмотра. Успешный тест не доказывает идентичное поведение серверных конвертеров, Synchrony или сторонних плагинов Atlassian.

## Запуск

Из корня репозитория:

```sh
npm install
npm run sandbox
```

Открыть <http://127.0.0.1:4177/>. Другой локальный порт:

```sh
SANDBOX_PORT=4180 npm run sandbox
```

Сервер слушает только `127.0.0.1`. Опции внешнего bind-host, прокси к другим сайтам и загрузки рабочих экспортов нет. Состояние страниц, черновиков и журнала хранится в памяти процесса. Перезапуск возвращает начальный каталог.

Для ручной проверки расширения:

```sh
npm run build:chrome
```

Загрузить `dist/` как распакованное расширение через `chrome://extensions`. Рекомендуется отдельный профиль браузера без рабочих cookie и старых настроек Confx. Не нужна веб-копия боковой панели или подмена `chrome.*`: страницы имеют обычные Confluence-подобные URL и метаданные, а расширение выполняет настоящий MAIN-world мост редактора.

### README demo capture (не native OS smoke)

Из корня: `npm run preview:readme`. Нужны Node ≥22, установленные npm dependencies,
bundled Chromium (`npx playwright install chromium`) и FFmpeg/ffprobe в PATH.
Отдельный loopback-порт по умолчанию 4189; переопределение:
`SANDBOX_E2E_PORT=4190 npm run preview:readme`. Занятый порт — ошибка, сервер не переиспользуется.
Обычная E2E suite на 4187 и ручной стенд на 4177 не затрагиваются.

Результаты EN/RU и receipts находятся в `tests/reports/readme-preview/staged/`.
После проверки PNG стадий, GIF frames, OCR и privacy gate публикация выполняется отдельно:
`node scripts/create-readme-previews.mjs --copy-to-docs`.
Driver проверяет hashes и текущий dist inventory, не перезаписывает публичные GIF при ошибке.
Capture показывает normal workspace и настоящий ZIP/download; CDP разрешает download
только в isolated test directory. Это не доказательство native side panel или OS dialogs.

## Обычный рабочий сценарий

1. Выбрать страницу, например Typography, и открыть режим редактирования.
2. Открыть Confx и выгрузить редактируемый Markdown из редактора либо полную страницу/раздел с `editable.md` в ZIP.
3. Отредактировать MD, сохранив служебные комментарии и защищённые блоки.
4. Загрузить файл в Confx, просмотреть изменения и подтвердить применение.
5. Проверить новое содержимое в настоящем TinyMCE и возможность отменить применение одним Undo.
6. При необходимости явно сохранить черновик. Для изменения опубликованной страницы нажать **Publish** в песочнице.
7. Перейти к просмотру или повторить экспорт и проверить сохранённые изменения.

Применение Confx меняет открытый редактор, не публикует страницу. Песочница использует явное сохранение черновика, а не имитацию фонового автосохранения Confluence. Публикация повышает версию; сохранение и удаление черновика — нет.

## Каталог

Все идентификаторы стабильны; основной корень — `1000`, пространство — `LOREM`.

| Страница        | ID   | Назначение                                                                             |
| --------------- | ---- | -------------------------------------------------------------------------------------- |
| Overview        | 1000 | Начальная страница, навигация и защищённый макрос                                      |
| Typography      | 1100 | Заголовки, выделение, цвета, переносы, пробелы и Unicode                               |
| Lists/tasks     | 1200 | Списки, вложенность и задачи                                                           |
| Tables          | 1300 | TH/TD-шапки, объединения, ячейки с кодом                                               |
| Code            | 1400 | Java, JavaScript, JSON, YAML, XML, SQL, inline/nested CODE и буквальные спецсимволы    |
| Macros          | 1500 | Панели, expand/status/code, TOC/children/excerpt, page properties и неизвестный макрос |
| Layouts         | 1600 | Одна, две и три колонки                                                                |
| Links/assets    | 1700 | Внутренние ссылки, якоря, изображения и локальные вложения                             |
| Nested specimen | 1710 | Внук корня, проверка иерархии и перекрёстных ссылок                                    |
| Combined        | 1800 | Составная страница с несколькими типами компонентов                                    |

Для каждой страницы в каталоге заданы поддерживаемые изменения и защищённые области. **Наличие элемента в витрине не означает, что его можно переписать через Markdown.** Самостоятельные списки, сложные таблицы и макросы могут оставаться защищёнными в соответствии с правилами Confx.

Неизвестные макросы показываются как неизвестные/защищённые, а не выдаются за рабочий сторонний плагин. Их исходные параметры и тело сохраняются непрозрачно. Поддерживаемые макросы имеют локальное представление для просмотра; это не копия серверного рендеринга Atlassian.

### Ограниченные read-only Jira specimens

Отдельный синтетический каталог содержит три задачи: `LOR-12`, `LOR-13`, `LOR-14`.
Откройте `/browse/LOR-12` на том же loopback-сервере для экспорта через настоящее расширение.
Поддерживаются только `GET /rest/api/2/issue/:key`, его `/comment`, поиск
`GET /rest/api/2/search` и локальные URL вложений. Запись issue, комментариев и вложений запрещена.

JQL ограничен `project = LOR` (опционально `ORDER BY key ASC`) либо `key = LOR-12`
и другими ключами этого каталога; это не универсальный JQL engine. Ответы используют
`startAt/maxResults/total`, максимум 50 элементов за запрос. Текущий JiraApi Confx по-прежнему
читает одну страницу поиска максимум из 50 задач; этот каталог не скрывает данный предел.
Нет Jira editor, reversible issue-body import, аутентификации или полной эмуляции Jira backend.

## Инспектор, журнал и сброс

Инспектор показывает опубликованные Storage/view/editor и отдельный черновик. Журнал различает чтение, преобразование, сохранение черновика и публикацию. Он хранит последние 200 записей; тела длиннее 4096 символов явно помечаются как обрезанные. Заголовки авторизации и cookie не записываются.

Лимиты кодека: 1,5 МиБ UTF-8 на исходник, глубина 128, 40 000 узлов. HTTP JSON-тело ограничено 2 МиБ. Черновик сохраняет собственную базовую версию, даже если опубликованная страница уже новее. Сохранение такого черновика не перебазирует его; попытка опубликовать поверх более новой версии отклоняется.

**Reset** требует подтверждения и восстанавливает начальные опубликованные страницы, очищает черновики и сценарии, увеличивает поколение состояния. UI передаёт поколение при сохранении, удалении черновика и публикации: запоздавшие записи предыдущего поколения отклоняются. Журнал и его монотонная нумерация сохраняются в пределах указанного ограничения. Уже скачанные файлы Reset не удаляет.

Журнал доступен также по `GET /sandbox/api/logs`, состояние — по `GET /sandbox/api/state`.

## Сценарии конфликтов

| Сценарий                   | Что проверяется                                                   |
| -------------------------- | ----------------------------------------------------------------- |
| `normal`                   | Обычный путь без намеренной ошибки                                |
| `published-newer`          | Новая опубликованная версия после экспорта                        |
| `published-source-changed` | Изменение опубликованного исходника при той же версии             |
| `draft-changed`            | Отдельная неопубликованная правка                                 |
| `conversion-loss`          | Потеря данных при преобразовании, которую импорт должен отклонить |

Сначала экспортировать базовый файл, затем включить нужный сценарий и попробовать применить локальную правку. Проверять не только сообщение, но и неизменность защищаемого опубликованного содержимого/черновика по инспектору и журналу.

`draft-changed` меняет сохранённый черновик, а не автоматически подменяет текущую native-копию. После включения этого сценария заново откройте режим редактирования, чтобы загрузить независимую правку, затем импортируйте ранее выгруженный файл. Стенд не имитирует доставку collaborative-изменений через Synchrony.

Возврат к `normal` выключает модификатор, но не откатывает уже изменённое содержимое. Для чистого повторения использовать Reset.

## Проверки

```sh
npm run test:sandbox
npm run build:chrome
npx playwright install chromium
npm run test:sandbox:e2e
```

Первая команда выполняет Node-тесты независимого кодека, HTTP API/состояния/безопасности и интеграцию с настоящим экспортным конвейером Confx. Ожидаемые правки текста, таблиц, кода и защищённых макросов проверяются отдельно от собственного roundtrip конвертера.

Браузерные проверки используют изолированный persistent-профиль bundled Chromium с настоящим распакованным `dist/` и настоящим TinyMCE. Обычный установленный Chrome не следует подставлять вместо bundled Chromium: актуальные Chrome/Edge ограничивают sideload-флаги расширений. Перед E2E должен существовать свежий Chrome build.

Если порт `4177` занят, E2E может поднять собственный чистый стенд на другом loopback-порту:

```sh
SANDBOX_E2E_PORT=4187 npm run test:sandbox:e2e
```

Этот параметр одновременно меняет server, base URL и network allowlist; reuse существующего
сервера не включается. Чужой процесс на `4177` не требуется останавливать или сбрасывать.

Артефакты тестов находятся в `tests/reports/sandbox/` и не включаются в репозиторий. Проверки не используют рабочий профиль, сеть рабочей wiki или реальные учётные записи.

Браузерный набор проверяет сохранение исходного Storage на всех десяти страницах после настоящей нормализации TinyMCE, экспорт страницы и всего дерева, применение изменённого MD к открытому редактору с подтверждением, отмену одной операцией Undo и публикацию только явной кнопкой самого стенда. В ConfX отсутствует route массовой публикации; Picker/Watch остаются доступны. Отдельно проверяются защищённые макросы, изменённая версия/исходник/черновик, потеря данных при конвертации и независимая правка редактора во время запроса. Полные тела преобразований для утверждений снимаются с реальных браузерных ответов; пользовательский журнал остаётся ограниченным.

Отдельный браузерный сценарий меняет разовый шаблон и front matter, проверяет фактический ZIP
и неизменность `chrome.storage.sync`, затем явно сохраняет defaults в settings schema 6.
Миграция v4→v5 по-прежнему переносит exportDefaults; только v5→v6 добавляет appearance palette.
Это проверка настоящего расширения и browser storage, не mock callback. Contracts также проверяют CSV-only service index
и отсутствие локальных ресурсов/sidecars при отключённых соответствующих параметрах.

`ConfxUi` ведёт сценарии через настоящий Composer: разделы **Export / Update page / Watch**,
области **Page / Subtree / Space / Fragment** или **Issue / Search / Fragment**, один **Template**,
видимые параметры пакета, radio-назначение и единственную кнопку **Start export**.
Проверяются реальные пакеты пространства и выбранного DOM-фрагмента, Jira issue/search,
CSV-only index, сохранение корня/фильтра/раскрытия и отменяемого задания при смене разделов.
Рабочая вкладка закреплена за явным source tab, даже когда активна другая страница.

Popup может выбрать многостраничный или дисковый экспорт, но **Continue in workspace tab**
лишь открывает новую нормальную вкладку и восстанавливает draft: задания, picker и скачивания
при этом не запускаются. **Choose file in workspace tab** открывает там раздел обновления без
автоматического file dialog; файл выбирается через реальный input уже в новой вкладке,
а содержимое файла и diff не передаются через session storage.

Сценарии трёх назначений сравнивают распакованный download ZIP с настоящими OPFS handles,
включая bytes ресурсов, terminal marker, отмену записи и коллизии существующих entries:

- **Download ZIP** — прежний `chrome.downloads` с `saveAs: true`; готовность только после
  browser download state `complete`.
- **New folder** — в выбранном parent создаётся новая `<safe-actual-package-root>-<jobUUID>/`;
  исходные файлы не переиспользуются, terminal marker отражает завершение или отмену.
- **ZIP to disk** — выбирается parent-папка, затем создаётся новый
  `<safe-actual-package-root>-<jobUUID>.zip`; готовность только после завершения ZIP, drain
  и `writable.close()`.

Оба дисковых назначения требуют secure normal workspace и `showDirectoryPicker({mode: "readwrite"})`.
ZIP на диск не выбирает существующий файл через Save File API: совпадение имени файла **или**
папки означает `destination-collision` без перезаписи. Отсутствие Save File API само по себе
не выключает этот режим; сценарий действительно сохраняет и распаковывает ZIP при таком условии.
Отмена между страницами прерывает новый writable, оставляет незавершённый новый ZIP и не меняет
другие файлы. Проверяются отсутствие ложного **Export ready**, поздних bytes/скачиваний и
освобождение общего export lock.

`ConfxUi.installExportPickers(parentName, { deferDirectory: true })` устанавливает в test seam
только `directory()` и наблюдатель `onPrepared({ id, rootName, destination })`. Без опции parent
возвращается сразу; с ней `resolveDeferredDirectoryPicker()` возвращает его после подготовки
коллизии. `lastPrepared()` даёт UUID и **подсказку** имени корня, не фактическое имя пакета.
Имя ZIP выводится из корня настоящего reference download и UUID, затем сверяется с terminal
receipt и физическим OPFS entry. Фиксированное имя не передаётся в writer через fixture.

Подменяется только получение parent directory handle, не filesystem, writer/close/abort или
controller. Файлы, папки, writable streams и чтение ZIP — настоящие OPFS-объекты extension origin.
Эти сценарии не доказывают работу системного выбора папки или input-файла: согласованная
нативная приёмка этого изменения выполняется отдельно в Vivaldi, включая Web Panel → normal tab.

Collection contracts проверяют пространство из 217 страниц с короткими непустыми пачками,
обход 6 001 дочерней страницы через API, tree cache и Watch snapshot, а также явный отказ
при повторных ID. Большие наборы создаются только в памяти теста через существующий store,
без debug endpoint. Локальный CQL ограничен space/type/label и экранированными строковыми
литералами; это не универсальная поисковая система Confluence.

Последовательные package contracts проверяют реальные ZIP bytes, backpressure, отмену
чтения Blob, канонические пути и коллизии, ссылки только на подтверждённые страницы и
fatal page-source failure без готового ZIP. Отдельный loopback HTTP-тест удерживает тело
ответа после отправки headers и проверяет timeout во время его чтения. Эти проверки не
доказывают работу системных file/directory dialogs или полную совместимость Atlassian.

## Реализация и границы

- `server.mjs`: loopback HTTP API, локальная версия/черновик/история, сценарии и журнал.
- `codec.mjs`: независимая обработка Storage XML и HTML; не импортирует конвертеры, identity-функции или патчер Confx как собственный серверный кодек.
- `catalog.mjs`: синтетические Lorem-источники и ожидания.
- `public/`: интерфейс, локальные ресурсы и настоящий TinyMCE.
- `tests/`, `e2e/`: самостоятельные ожидания и проверки реального потребителя Confx; `e2e/fixtures.mjs` связывает настоящий UI с синтетическим source-каталогом и предоставляет только parent-directory picker seam для дисковых экспортов.

Основные HTML-конструкции, layout и непрозрачные макросы поддержаны явно. Небезопасные или неподдерживаемые конструкции отклоняются, а не молча удаляются и не заменяются исходной заготовкой. Стенд не является универсальным импортёром произвольного Confluence HTML/XML.

Не воспроизводятся SSO, права и enterprise-политики, collaborative editing/Synchrony, серверные баги конкретной версии Atlassian, реальный draw.io/PlantUML, полный Jira backend и произвольные Marketplace apps. Для текущего рабочего конфликта импорта всё ещё необходима независимая фиксация фактических представлений той системы; локальный успех не отменяет её защитных проверок.

## Источники и лицензии

Структура компонентов ориентируется на публичный [Confluence Storage Format](https://confluence.atlassian.com/doc/confluence-storage-format-790796544.html) и модель [confluence-content-parser](https://confluence-content-parser.readthedocs.io/en/latest/) (Apache-2.0). Последний — парсер XML в дерево, не рендерер Confluence и не обратный серверный конвертер. Его Python-код не копируется и не требуется для запуска.

TinyMCE `8.10.2` — отдельная devDependency, self-hosted из `node_modules/tinymce`, с `license_key: "gpl"`. Действует GPLv2+ либо отдельная коммерческая лицензия Tiny; см. `node_modules/tinymce/license.md` и [официальную страницу](https://www.tiny.cloud/get-tiny/self-hosted/). Runtime не включается в сборку пользовательского расширения. При распространении песочницы необходимо сохранять условия и уведомления зависимостей; код и ресурсы Atlassian не копируются.
